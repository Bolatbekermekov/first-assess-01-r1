# Что проверяет независимый reviewer

Обязательные условия приёмки:

- контракт соблюдён, включая точные статусы, порядок кодов ошибок и формат JSON;
- показаны реальные JSON/CSV CLI запуски и все публичные проверки;
- собственные тесты покрывают правила, которые не исчерпываются видимыми примерами: Unicode NFC/casefold, граничные длины, malformed CSV/quoted cells, JSON duplicate keys на вложенном уровне, blank vs populated metadata conflict, представитель первого ряда, symlink/existing output и ошибки файловой системы;
- логика не подменяется lookup-таблицей по fixtures, нет заранее записанного отчёта вместо вычисления;
- входы и чужие файлы не изменяются, ошибки не раскрывают сырые данные;
- HTML отображает весь результат и безопасно экранирует текст;
- пакет запускается без сторонних библиотек, сети и модулей других разработчиков;
- код разделяет parsing/validation/grouping/presentation, оставаясь понятным без лишнего framework;
- возврат воспроизводим, ограничения честно описаны, предложенная декомпозиция пригодна для независимой проверки частей.

Публичные тесты — минимальная видимая выборка. Reviewer проверяет дополнительные входы по тому же контракту. Провал обязательного поведения требует доработки; оформление не компенсирует неверный алгоритм. Наличие красивого HTML само по себе не доказывает качество обработки данных.
