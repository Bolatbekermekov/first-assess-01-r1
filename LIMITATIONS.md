# LIMITATIONS — FIRST-ASSESS-01 R1

## 1. Неоднозначности контракта и принятые решения

Полная таблица с обоснованиями — `docs/CP1_DESIGN.md`, раздел 10. Каждое решение закреплено тестом (`TEST_MATRIX.md`). Если проверяющий трактует пункт иначе, изменение локально: одна функция в одном модуле.

| ID | Решение | Пример фактического поведения |
|---|---|---|
| A1 | `contact_email`: проверки выполняются после `strip().lower()` — контракт говорит «пределы применяются после нормализации» | KELVIN SIGN (U+212A) после `lower()` превращается в ASCII `k`; email из U+212A и `ate@example.test` валиден и нормализуется в `kate@example.test` |
| A2 | `country_code`: проверка после `strip().upper()` | `ß` → `SS`, `ſe` → `SE`, `ıt` → `IT`, `ﬀ` → `FF` — валидные коды (только синтаксис, не справочник стран) |
| A3 | Общее правило запрещает только C0, DEL и суррогаты | Unicode-пробелы (NBSP, U+2028, U+3000 и др.) молча срезаются `strip()`/`split()`. C1-символы и форматирующие символы (U+200B, U+202E, U+FEFF) в `company_name` и `source_ref` допустимы и показываются как есть. В ASCII-полях они отвергаются их собственным синтаксисом |
| A4 | CSV разбирается `csv.reader` так, как предписывает контракт | Одиночный CR принимается как конец записи — так работает `csv.reader` при `newline=""`; отличить его внутри кавычек без собственного парсера нельзя. «Голая» кавычка внутри некавыченной ячейки (`Ex"ample`) сохраняется как данные |
| A5 | Снимается ровно один BOM | Второй BOM даёт `INVALID_DOCUMENT`, а не `INVALID_ENCODING`: декодирование прошло, синтаксис — нет |
| A6 | Целые длиннее 4300 цифр → `INVALID_DOCUMENT` | Это защита CPython от квадратичной конверсии (`sys.get_int_max_str_digits()`); такой элемент всё равно был бы REJECTED |
| A7 | Своего лимита вложенности JSON нет, перехватывается только `RecursionError` | Граница зависит от сборки интерпретатора и глубины стека (на CPython 3.12.13 около 9997 уровней) |
| A8 | Только точные builtin-типы | Ряд-`OrderedDict` → `INVALID_ROW_SCHEMA`; подкласс `str` в поле → код поля; `bytearray`/`memoryview` → `INVALID_DATA` |
| A9 | У `--format` нет `choices` в argparse | `--format xml` даёт `ERROR INVALID_FORMAT` без эха значения. Если вход нечитаем, раньше сработает `IO_ERROR`: чтение идёт до `load_rows` |
| A10 | Hostname проверяется только синтаксически | `https://1.2.3.4/` и числовые TLD валидны |
| A11 | Число `1e400` — валидный JSON | Становится `inf` и передаётся в анализатор, где даёт REJECTED |
| A12 | Ключи CSV-ряда идут в каноническом порядке полей | `row_number` — номер записи данных без заголовка, а не физической строки (quoted-ячейка может занимать несколько строк) |
| A13 | `--out-dir ""` не превращается в `.` | `IO_ERROR` |
| A14 | Права каталога и файлов — по umask (`0o777` / `0o666`) | Отчёты содержат email; ограничить доступ — ответственность вызывающего (например, `umask 077`) |
| A15 | `render_html` не перепроверяет отчёт (контракт это разрешает) | Неизвестный статус получает нейтральный стиль; значения всё равно экранируются |

## 2. Платформенные ограничения

- **Версия Unicode.** NFC, `casefold`, `lower`, `upper`, `strip` и `split` зависят от базы Unicode интерпретатора (`unicodedata` 15.0.0 в CPython 3.12). На других минорных версиях Python результаты для новых символов могут отличаться.
- **`csv.field_size_limit`** — глобальная настройка процесса. Модуль меняет её только на время разбора CSV, под `threading.Lock`, и восстанавливает в `finally`. Параллельные вызовы `load_rows` не мешают друг другу. Чужой код, читающий CSV в другом потоке в тот же момент, может увидеть поднятый лимит.
- **Память.** Вход до 10 MiB, его разобранная структура и HTML-отчёт целиком находятся в памяти. На 10 000 рядов HTML занимает единицы мегабайт.
- **Сбой записи.** При ошибке записи после создания каталога он остаётся частично заполненным, как разрешает контракт. Успех не заявляется, чужие пути не удаляются.
- **Платформа.** Защита записи `O_DIRECTORY | O_NOFOLLOW` + `dir_fd` + `O_EXCL` работает на POSIX. Без `dir_fd` (Windows) используется только `O_EXCL` по полному пути, без защиты от подмены каталога между `mkdir` и записью. На Windows не запускалось.
- **Окружение проверок.** Запуски были только на Linux (Docker-контейнер Debian 13, aarch64) и macOS 26.6.2 (arm64), оба с CPython 3.12.13. Другие ОС и версии не проверялись.

## 3. Что модуль сознательно не делает

- Не проверяет существование компании, доставляемость email, наличие MX-записей и разрешение на контакт. Статус UNIQUE означает только, что в текущем наборе нет другого валидного ряда с тем же email.
- Не выдаёт outbound/send/qualified-разрешений и не выполняет скоринг.
- Не выполняет fuzzy-дедупликацию: `+tag`, точки в local part и похожие домены различаются.
- Не поддерживает IDN в email и URL (только ASCII и punycode как ASCII), кавычечные local part и IP-литералы `[…]`. Не применяет NFKC, транслитерацию, URL decode и HTML unescape.
- Сравнение названий использует ровно ключ контракта `casefold()` после NFC, без полного канонического caseless matching Unicode. Поэтому `İstanbul` и `istanbul` различаются, а `Straße` и `STRASSE` совпадают.
- Невидимые и bidi-символы, разрешённые общим правилом (A3), показываются в HTML как есть. Каждое значение стоит в своей ячейке, поэтому они не затрагивают соседние ячейки, но внутри своей ячейки могут быть незаметны.

## 4. Процесс и состав возврата

- Dev-окружение не входит в возврат: Docker Compose-песочница без сети и не от root, скрипты журналов, мутационной проверки и упаковки. `RETURN_INSTRUCTIONS.md` разрешает только перечисленные пути. Каждый журнал в `logs/` начинается с точной команды и среды выполнения.
- Мутационная проверка (`logs/15_mutation_smoke.txt`) — dev-скрипт: он временно вносит дефект в модуль и запускает соответствующие тесты. Сам скрипт в возврат не входит; список дефектов и результат видны в журнале.
- Свойства и инварианты (`test_candidate_properties.py`) используют фиксированный seed. Это воспроизводимая выборка, а не исчерпывающий перебор.
