## 1. Цель и границы

Цель — локальный модуль `assess_workbench` на Python 3.12 и только стандартной библиотеке: API `load_rows` / `analyze_rows` / `render_html`, CLI и собственный набор тестов. Результат детерминирован и воспроизводим.

Вне рамок (`00_READ_FIRST_RU.md`, «Границы»): сеть, веб-сервер, БД, авторизация, редактирование, fuzzy matching, скоринг, проверка существования компании или доставляемости email, разрешения на контакт (outbound/send/qualified). Статус `UNIQUE` означает только отсутствие другого валидного ряда с тем же email в текущем наборе.

## 2. Архитектура

Функциональное ядро и тонкая оболочка. Вычисления — чистые функции без состояния на уровне модуля; файловый ввод-вывод только в `cli.py`.

```text
assess_workbench/
  __init__.py      докстринг; ничего не импортирует и не выполняет
  __main__.py      python -m assess_workbench -> cli.main()
  api.py           фасад контракта: WorkbenchError, load_rows, analyze_rows, render_html
  errors.py        WorkbenchError и коды ошибок API
  contract.py      константы контракта: поля, статусы, коды, лимиты, версии схем, типы отчёта
  loading.py       parsing:      bytes -> list (лимиты, UTF-8/BOM, JSON, CSV)
  fields.py        validation:   общее правило и нормализация шести полей
  grouping.py      grouping:     email-группы -> UNIQUE / DUPLICATE / CONFLICT
  analysis.py      проверка scope и сборка отчёта
  html_report.py   presentation: отчёт -> автономный HTML (шаблон внутри .py)
  cli.py           оболочка: argparse, чтение входа, безопасная запись, коды выхода
```

Зависимости (стрелка — «импортирует»):

```text
__main__ -> cli -> api -> loading     -> errors, contract
                       -> analysis    -> fields, grouping, errors, contract
                       -> html_report -> contract
```

Принципы:

- Точные builtin-типы (`type(x) is dict`, а не `isinstance`): подклассы dict/list/str/bytes отвергаются (решение A8). `bool` нигде не принимается за `int`.
- В выходе только `dict`, `list`, `str`, `int`, `None`. Константы — обычные `str`, не `Enum`: проверка `type(code) is str` у потребителя должна проходить.
- Выход не разделяет изменяемых объектов ни с входом, ни между рядами: на каждый ряд создаются новые `dict` и `list`.
- `WorkbenchError` поднимается вне блоков `except`, поэтому у него нет `__cause__` и `__context__`. Исходные исключения хранят весь вход (`UnicodeDecodeError.object`, `JSONDecodeError.doc`) и не должны утечь ни в traceback, ни через атрибуты.
- Импорт пакета не имеет побочных эффектов. `csv.field_size_limit` меняется только на время разбора CSV. **R2:** другие настройки процесса, в том числе `sys.set_int_max_str_digits` и предел рекурсии, не меняются и на результат не влияют.
- Схема отчёта описана через `TypedDict` (во время выполнения это обычные `dict`), промежуточные результаты — через `dataclass(frozen=True, slots=True)`. Полная типизация, проверяется `mypy --strict`.

## 4. Парсер: `load_rows(data, *, format)`

Проверки строго в порядке контракта:

1. `type(data) is bytes`, иначе `INVALID_DATA`. Это же правило отвергает `bytearray`, `memoryview` и `str`.
2. `type(format) is str` и `format` равен `"json"` или `"csv"` с учётом регистра, иначе `INVALID_FORMAT`.
3. `len(data) <= 10_485_760`, иначе `INPUT_TOO_LARGE`. Лимит включительный, BOM входит в число байтов.
4. `data.decode("utf-8-sig")` в строгом режиме снимает ровно один BOM в начале. `UnicodeDecodeError` даёт `INVALID_ENCODING`, в том числе на закодированных суррогатах и overlong-последовательностях.
5. Синтаксис и структура — `INVALID_DOCUMENT` (ниже).
6. `len(rows) > 10_000` — `TOO_MANY_ROWS`, только после полного успешного разбора.

**JSON.** `json.loads` с хуками:
- `object_pairs_hook` отвергает повтор ключа в любом объекте на любой вложенности. Сравниваются ключи после разэкранирования, поэтому `"a"` и `"a"` — дубль.
- `parse_constant` отвергает `NaN`, `Infinity`, `-Infinity`.
- **R2:** `parse_int` переводит целый литерал в `int` с точным значением при любом `sys.set_int_max_str_digits`.
  - Литерал до 640 цифр переводится обычным `int()`: на такую длину лимит не распространяется.
  - Более длинный режется на куски по 640 цифр, которые склеиваются арифметикой.
  - Без этого хука `int()` отвергал литералы длиннее глобального лимита процесса, и документ становился `INVALID_DOCUMENT` в зависимости от настроек интерпретатора (решение A6).

Перехватываются `ValueError` (включая `JSONDecodeError`) и `RecursionError`. Корень обязан быть `list` (точный тип). После корня `json` допускает только JSON whitespace. Элементы массива возвращаются без изменений — их оценивает `analyze_rows`.

**CSV.** `csv.reader(io.StringIO(text, newline=""), delimiter=",", quotechar='"', doublequote=True, strict=True)`.

Работа с `csv.field_size_limit` идёт под `threading.Lock`: значение сохраняется, поднимается до 10 485 760 (самое длинное возможное поле в допустимом файле) и восстанавливается в `finally`.

Документ разбирается целиком, затем проверяется структура:
- нет ни одной записи (пустой файл) — `INVALID_DOCUMENT`;
- заголовок: ровно 6 ячеек, а множество имён совпадает с шестью полями — это же исключает повторы. Имена не обрезаются и не приводятся к регистру;
- в каждой записи ровно 6 ячеек; пустая физическая запись `[]` — `INVALID_DOCUMENT`;
- `csv.Error` — `INVALID_DOCUMENT`;
- только заголовок — `[]`;
- ряд становится `dict` в каноническом порядке полей, даже если в заголовке другой порядок.

## 5. Валидация и нормализация полей

Проверка ряда:

- не `dict` или множество ключей не равно шести полям → `REJECTED`, `[INVALID_ROW_SCHEMA]`, поля дальше не проверяются;
- иначе поля проверяются в порядке `company_name, contact_email, website_url, country_code, language, source_ref`. Для каждого сначала общее правило на исходном значении, затем нормализация и пределы. Не более одного кода на поле; коды накапливаются по этому порядку.

**Общее правило** (на исходном значении): `type(v) is str`, `len(v) <= 4096`, нет символов `U+0000–U+001F`, `U+007F`, `U+D800–U+DFFF`. Проверка — один предкомпилированный regex. Следствие: таб и перевод строки запрещены даже по краям, хотя `strip()` бы их удалил.

| Поле | Шаги после общего правила |
|---|---|
| `company_name` | `NFC` → `" ".join(v.split())` → длина 1..200 |
| `contact_email` | `strip().lower()` → `isascii()` → длина ≤ 254 → fullmatch regex контракта → local-часть ≤ 64, не начинается и не заканчивается `.`, нет `..` → каждая label домена ≤ 63 |
| `website_url` | `strip()`; пустая строка остаётся `""`. Иначе последовательно: длина ≤ 2048 → ASCII → нет ASCII-whitespace → префикс ровно `https://` → нет `#` в строке → `urlsplit` (его `ValueError` = невалидно) → в netloc нет `:`, `@`, `[`, `]` → hostname непустой и ≤ 253, в нём ≥ 2 label, каждая ≤ 63 и проходит label-regex → `urlunsplit(("https", hostname, path, query, ""))` |
| `country_code` | `strip().upper()` → `""` или fullmatch `[A-Z]{2}` |
| `language` | `strip()` → `""` или fullmatch `([A-Za-z]{2})(?:-([A-Za-z]{2}))?` → `primary.lower()`, при наличии `-REGION.upper()` |
| `source_ref` | `strip()` → длина 1..200; регистр и внутренние пробелы сохраняются |

`#` ищется в самой строке, потому что `urlsplit` не отличает пустой фрагмент от отсутствующего: для `https://a.b/#` он вернёт `fragment == ''`.

Все regex используют явные ASCII-классы и флаг `re.ASCII`, без `re.IGNORECASE`: с ним `[a-z]` в Python совпадает с `ſ` (U+017F) и `K` (U+212A). Не выполняются HTML unescape, URL decode, транслитерация и NFKC.

Любое невалидное поле → `REJECTED`, `normalized = null`, `duplicate_of_row = null`, и ряд не участвует в группировке.

## 6. Группировка

1. Валидные ряды группируются по точному нормализованному `contact_email`: словарь email → список номеров рядов в порядке входа.
2. Ключ метаданных: `(company_name.casefold(), website_url, country_code, language)`. `source_ref` в ключ не входит.
3. Если в группе ≥ 2 различных ключей → все её ряды `CONFLICT`, `[EMAIL_METADATA_CONFLICT]`, `duplicate_of_row = null`.
4. Иначе первый ряд `UNIQUE`, `[VALID_RECORD]`, а остальные `DUPLICATE`, `[EXACT_DUPLICATE]` с `duplicate_of_row` = номер первого ряда. Группа из одного ряда — частный случай этого правила.

Сложность O(n) по числу рядов. Поля рядов не сливаются: `company_name` в выходе — нормализованное значение своего ряда.

## 7. Отчёт: `analyze_rows(rows, *, scope)`

Предусловия в порядке контракта:
1. `INVALID_SCOPE`: scope — точный `dict` ровно с тремя ключами; `schema_version` точно равен `"ASSESS_SCOPE_V1"`; `client_id` и `campaign_id` — `str` с fullmatch `[A-Za-z0-9][A-Za-z0-9_.:-]{0,127}`.
2. `INVALID_ROWS`: `rows` — точный `list`.
3. `TOO_MANY_ROWS`: в `rows` больше 10 000 элементов.

Результат — новый `dict`:
- `schema_version = "ASSESS_LEAD_REPORT_V1"`;
- `scope` — новый `dict` из трёх проверенных значений;
- `summary` — `total`, `unique`, `duplicate`, `conflict`, `rejected` как счётчики рядов, `total` равен их сумме;
- `rows` — в порядке входа, `row_number` с 1.

Без времени, случайных ID, сырого входа и разрешений.

## 8. HTML: `render_html(report)`

**Структура документа.**
- Полный документ: `<!DOCTYPE html>`, `<html lang="ru">`.
- `<head>`: `<meta charset="utf-8">`, viewport, `<title>`, встроенный статический `<style>`. Плюс CSP `default-src 'none'; style-src 'unsafe-inline'` — защита в глубину: даже при ошибке ничего не загрузится и не исполнится.

**Разделы.**
- scope и сводка;
- пояснение семантики статусов: `UNIQUE` не означает разрешение на контакт;
- таблица всех рядов: номер, статус, коды с человекочитаемым объяснением, шесть нормализованных полей, `duplicate_of_row`;
- легенда кодов.

Для `REJECTED` вместо полей — коды, объяснения и фраза «нормализованные значения отсутствуют; исходные данные не показываются». Пустой набор сопровождается явным сообщением.

**Экранирование.**
- Каждое значение из отчёта (scope, поля, коды, статусы, числа) вставляется только как текст через `html.escape(str(value), quote=True)`.
- Атрибуты только статические. CSS-класс статуса берётся из фиксированного словаря, а не из данных.
- Нет `<a>`, `href`, `src`, `<script>`, `<iframe>`, `<form>`, `<link>`, `<img>`, CSS `url(` и `@import`, JavaScript и сетевых адресов.

**Поля не скрываются и не сокращаются.**
- `white-space: pre-wrap` — видны внутренние пробелы `source_ref`.
- `overflow-wrap: anywhere`; никаких `text-overflow` и `overflow: hidden`.
- Пустая строка помечается CSS-псевдоэлементом, а не текстом, который можно спутать с данными.
- Каждое значение стоит в своей ячейке: каждая ячейка — отдельный bidi-абзац, поэтому управляющие символы направления (например, U+202E) не затрагивают соседние ячейки.

**Детерминизм.** Документ строится только из данных отчёта, без времени и окружения.

## 9. CLI

```text
python -m assess_workbench --input FILE --format json|csv --client-id ID --campaign-id ID --out-dir NEW_DIRECTORY
```

**Аргументы.** argparse, все пять параметров обязательны, `allow_abbrev=False`. У `--format` нет `choices` (решение A9). Ошибка аргументов — стандартное сообщение argparse и exit 2.

**Шаги.** При любой ошибке после разбора аргументов stdout пуст, stderr ровно `ERROR <CODE>\n`, exit 2.

1. Чтение: `open(input, "rb")` и `read(10_485_761)`. `OSError` → `IO_ERROR`. Файл больше лимита целиком не читается.
2. `load_rows` → `analyze_rows` → `render_html`. `WorkbenchError` → его код.
3. Сборка байтов в памяти:
   - JSON: `json.dumps(report, ensure_ascii=False, sort_keys=True, indent=2) + "\n"`, UTF-8 без BOM;
   - HTML: UTF-8 без BOM.
4. Закрепление и создание (**R5**): родитель открывается `O_DIRECTORY | O_NOFOLLOW` и фиксируется дескриптором **до создания**; проверяется его доверенность; затем `os.mkdir(name, 0o700, dir_fd=parent)` — относительно дескриптора, режим только владельцу.
   - `FileExistsError` → `OUTPUT_EXISTS`: существующий путь любого типа, symlink, висячий symlink, гонка.
   - Иная `OSError` → `IO_ERROR`: нет родителя, родитель не каталог, нет прав.
   - Предварительной проверки `exists()` нет: для висячего symlink она возвращает `False` и открывает окно гонки.
5. Запись: каталог открывается с `O_RDONLY | O_DIRECTORY | O_NOFOLLOW`, файлы создаются относительно его дескриптора с `O_WRONLY | O_CREAT | O_EXCL | O_NOFOLLOW`. Существующий файл не перезаписывается, symlink с именем отчёта не разыменовывается.
   - **R2, исправление.** В R1 здесь было написано: «даже если путь подменят между шагами, запись не уйдёт за пределы своего каталога». Это неверно. `mkdir()` не возвращает дескриптор, поэтому каталог открывается заново по пути. Обычный каталог, поставленный на место созданного до открытия, `O_NOFOLLOW` не останавливает. При `/` в конце пути ядро разрешает и symlink.
   - **R2, проверки.** Хвостовые `/` убираются перед открытием. Открытый каталог должен быть пуст. После записи путь должен указывать на тот же каталог (`os.path.samestat`). Иначе `IO_ERROR`.
   - **R5, порядок.** Родитель закреплён и проверен на доверенность до создания (шаг 4); `mkdir`/`open`/запись идут относительно дескриптора, повторного разбора пути нет — подменить родителя «между `mkdir` и открытием» нельзя. При недоверенном родителе — `IO_ERROR` до создания.
   - **R5, финальная проверка.** После записи успех — только если `samestat` подтверждает, что открытый out-dir тот же, что мы создали, **и** путь родителя указывает на закреплённый родитель. Иначе `IO_ERROR`: путь перенаправили после закрепления.
   - **Защита в глубину (не доказательство).** Проверки владельца/режима/пустоты открытого каталога. Доказать тождество открытого каталога созданному в POSIX/stdlib нельзя.
   - **Граница.** В доверенном родителе переименовать out-dir в окне может только тот же пользователь или root — вне модели угроз. Вышележащие каталоги предполагаются доверенными. Условие эксплуатации — `docs/R5_REWORK.md`, раздел 4.
   - Сбой записи → `IO_ERROR`. Частичный каталог остаётся, успех не заявляется, ничего не удаляется.
   - Без поддержки `dir_fd` (например, Windows) — запасной путь: `O_EXCL` по полному пути, без проверок R2–R4.

**Успех.** В каталоге ровно `report.json` и `report.html`; stdout `REPORT_CREATED\n`; stderr пуст; exit 0.

**Перехват исключений.** Ловятся только `WorkbenchError` и `OSError`. `KeyboardInterrupt` и `SystemExit` не перехватываются. Общего `except Exception` нет: контракт не определяет код для внутренней ошибки.

## 10. Неоднозначности контракта и принятые решения

Каждый пункт проверен на CPython 3.12.13, закреплён тестом и записан в `LIMITATIONS.md`.

| ID | Место | Неоднозначность | Решение |
|---|---|---|---|
| A1 | email | `strip().lower()` выполняется до проверки ASCII, а `K` (U+212A KELVIN SIGN) после `lower()` становится ASCII-буквой `k` | Сначала нормализация, затем проверки: контракт говорит, что «пределы применяются после нормализации». `"\u212Aate@example.test"` валиден и даёт `kate@example.test` |
| A2 | country_code | `upper()` переводит `ß`→`SS`, `ı`→`I`, `ſ`→`S`, лигатуры `ﬀ`→`FF`, `ﬆ`→`ST` | Так же буквально: `ß` валиден и даёт `SS` |
| A3 | все поля | Юникод-пробелы вне ASCII (NBSP, U+0085, U+2028, U+3000 и др.) общим правилом не запрещены и удаляются `strip()`/`split()`. C1-символы (U+0080–U+009F) и форматирующие (U+200B, U+202E, U+FEFF) разрешены | Буквально; в HTML показываются как есть, каждое значение в своей ячейке |
| A4 | CSV | Контракт говорит «CRLF или LF», но `csv.reader` с `newline=""` принимает и одиночный CR как конец записи | Поведение `csv.reader`, который предписан контрактом. Одиночный CR внутри кавычек без собственного парсера неотличим |
| A5 | кодировка | Второй BOM после первого — это `INVALID_ENCODING` или `INVALID_DOCUMENT`? | Снимается ровно один BOM; декодирование успешно, а оставшийся U+FEFF не проходит синтаксис → `INVALID_DOCUMENT` |
| A6 | JSON | На целых длиннее `sys.get_int_max_str_digits()` (по умолчанию 4300) `int()` бросает `ValueError` — это защита от квадратичной конверсии (CVE-2020-10735) | **R2:** целое любой длины загружается с точным значением через хук `parse_int`, независимо от настройки, и отклоняется анализатором. Решение R1 (`INVALID_DOCUMENT`) было ошибкой: результат зависел от глобальной настройки процесса, а лимита цифр в контракте нет |
| A7 | JSON | Предел вложенности зависит от сборки (здесь 9997) | Только перехват `RecursionError`, без собственного лимита. **R2:** проверено, что граница — константа сборки и от `sys.setrecursionlimit` не зависит |
| A8 | типы | Подклассы dict/list/str «не требуется поддерживать» | Отвергаются: ряд-`OrderedDict` → `INVALID_ROW_SCHEMA`, подкласс dict в scope → `INVALID_SCOPE`, подкласс list → `INVALID_ROWS`, подкласс str в поле → код поля, `bytearray`/`memoryview` → `INVALID_DATA` |
| A9 | CLI | Для `--format` вне json/csv: argparse `choices` или код контракта? | Без `choices`: `ERROR INVALID_FORMAT`, значение пользователя не печатается. Следствие: если вход ещё и нечитаем, будет `IO_ERROR` — чтение идёт раньше `load_rows` |
| A10 | website_url | IPv4-подобные хосты и числовые TLD (`https://1.2.3.4`) проходят label-regex | Буквально: контракт проверяет только синтаксис |
| A11 | JSON | `1e400` — синтаксически валидное число; Python превращает его в `inf` | Это не ошибка документа: элемент уходит в анализатор и даёт `REJECTED` |
| A12 | CSV | Порядок ключей ряда и смысл номера ряда | Ключи в каноническом порядке полей; `row_number` — номер записи данных без заголовка, а не номер физической строки |
| A13 | CLI | `--out-dir ""` | Путь не нормализуется через pathlib (иначе `""` превратился бы в `.`): `mkdir("")` → `IO_ERROR` |
| A14 | CLI | Права создаваемых каталога и файлов | Стандартные с учётом umask (`0o777` / `0o666`), без chmod |
| A15 | HTML | Отчёт, полученный не из `analyze_rows` | Повторной валидации нет — контракт это разрешает. Неизвестный статус получает нейтральный стиль, значения всё равно экранируются |
| A16 | CLI | **R5.** Модель угроз после `mkdir`: процесс с правом записи в родителя может переименовать подходящий каталог в нужное место. Доказать тождество открытого каталога созданному в stdlib нельзя — защита строится на родителе и порядке | Родитель закрепляется дескриптором и проверяется на доверенность (наш или root, не групп/прочим-записываемый либо sticky) **до создания**; иначе `IO_ERROR` до создания. `mkdir`/`open`/запись — относительно дескриптора, без повторного разбора пути. После записи `samestat` подтверждает out-dir и путь родителя, иначе `IO_ERROR`. Защита в глубину (не доказательство): владелец/режим/пустота. symlink (в т. ч. при `/` в конце), непустой каталог, каталог группе/прочим, подмена после открытия → `IO_ERROR`. Необнаружим перенос тем же пользователем в доверенном родителе — вне модели угроз. Условие — `docs/R5_REWORK.md`, раздел 4 |

## 12. Окружение и доказательства

- **Разработка и прогоны — в Docker, только как dev-окружение.** `compose.yaml` лежит в рабочей папке:
  - образ `python:3.12-slim` с зафиксированной версией, проект смонтирован в `/work`;
  - процесс запускается не от root, `network_mode: none`, `PYTHONDONTWRITEBYTECODE=1`;
  - корневая ФС только для чтения, `/tmp` — tmpfs.

  `compose.yaml` и другие dev-файлы в возврат не входят: `RETURN_INSTRUCTIONS.md` их не разрешает, а `00_READ_FIRST_RU.md` говорит, что Docker не нужен. Продукт запускается обычным `python` без Docker.
- **Дополнительный прогон на macOS** уже установленным CPython 3.12.13, без скачиваний — второе подтверждение POSIX-семантики, на APFS.
- **Статический анализ** (dev-инструменты, не зависимости продукта): `ruff check`, `ruff format --check`, `mypy --strict`.
- **Журналы.** Фактическая среда (`python -VV`, платформа, образ) записывается в `logs/`. В `evidence/` — только вывод `RUN_ACCEPTANCE.py`.
